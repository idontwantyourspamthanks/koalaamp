# PL-1 · Playlist persistence + formats

- **Milestone:** M1 · **Est:** 3d · **Depends:** SE-3, FE-4 · **Status:** in-review

## Story
Every playlist format a Winamp user's disk actually contains, read and written faithfully enough that files round-trip without loss: M3U/M3U8 (byte-exact `#EXTINF` emission), PLS, B4S, XSPF, ASX/WPL, the Media Library `playlists.xml` index, plus autosave so a crash doesn't eat the queue.

## REUSE, DON'T REIMPLEMENT
- **The in-memory model exists** (`src/ui/PleditState` from SE-3: entries with title/length, queue positions, selection) and its **ATF subset** (`src/ui/Atf.cpp`). PL-1 is *serialisation*: read files → model, write model → files. No new UI.
- **The queue/transport surface is FE-4's** (`PlaybackCore` via `ITransport`); loading a playlist into playback is `clearQueue` + `enqueue` calls, already exposed.
- **`docs/research/formats.md` §1-2 is the spec** for every format, source-verified: the exact M3U writer emission (`#EXTM3U\n`, `#EXTINF:<seconds>,<title>\n<path>\n`), M3U8's UTF-8 BOM (`EF BB BF`) *before* `#EXTM3U`, the loader's leniency (directives recognised, unknown `#` lines ignored, `ASF ` prefix stripped, relative paths resolved against the playlist's folder), PLS's INI shape, B4S's XML (`WasabiXML`/`WinampXML`, `entry playstring`), and the `playlists.xml` index fields.
- Path handling: reuse `src/skins/SkinDb`'s `keyFor` canonicalisation pattern (and its lesson: canonicalise persistently, not per-read) where track paths need stable identity.

## Notes / risks
- The M3U8 BOM is the detail everyone gets wrong: Winamp writes `EF BB BF` then `#EXTM3U`, and its reader accepts either. Match the writer exactly or the round-trip test won't.
- `#EXTAUTOSTART` is **not** a Winamp extension (formats.md §1) — do not "support" it as one.
- Path canonicalisation on Windows bit us in SE-4 (`weakly_canonical` resolving relative to the current drive): canonicalise once on load, store the canonical form, never compare a raw path against a canonicalised one.

## Outcome / decisions (implemented)

- **Module:** `src/playlist/` — Qt-free static lib `koalaamp_playlist` (`Track.hpp`, `Playlist.hpp/.cpp`, `M3u.cpp`, `Pls.cpp`, `B4s.cpp`, `Xspf.cpp`, `Asx.cpp`, `Xml.hpp/.cpp`, `Util.hpp/.cpp`). `src/ui` converts `PleditEntry` → `playlist::Track` at the window verbs; the module has no Qt/UI/playback dependency (grep-asserted by a test).
- **Write set:** M3U, M3U8, PLS, B4S, XSPF. **ASX/WPL are read-only** (the recorded choice): neither is a Winamp round-trip target, and `.wax`/`.wvx` are ASX aliases.
- **Autosave location:** `<AppDataLocation>/playlist/playlist.m3u8` + `playlist.state` — the SkinDb-style single-state-file decision (the M3U8 holds the rows; the sidecar the queue order + playing index). Both written atomically (temp + rename), so a kill -9 leaves the previous pair intact and a stale `.tmp` is ignored.
- **Byte-exact M3U8:** `tests/fixtures/playlist/emission.m3u8` (hand-authored, ours) — BOM `EF BB BF` + `#EXTM3U`, `#EXTINF:<secs>,<title>`, UTF-8 titles, and a metadata-less bare-filename row. The writer-test compares against it byte-for-byte; the plain M3U is the same bytes without the BOM.
- **Extension list:** `playlist::supportedExtensions()` (`.m3u .m3u8 .pls .b4s .xspf .asx .wax .wvx .wpl`) is the parser-owned list the SE-3 window verbs and CO-1 file associations consume.
- **Evidence:** `koalaamp_playlist_tests` (31 cases), `koalaamp_playlist_fuzz_tests` (3 cases / 100 mutated inputs) and `koalaamp_pl1_window_tests` (6 cases) all green; the two Qt-free suites are ASAN+UBSAN clean (leak detection on).
- **`#EXTAUTOSTART`:** never treated as a Winamp directive (a test pins it).
