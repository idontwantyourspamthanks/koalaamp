# SV-2 · Jellyfin playback + progress + remote control

- **Milestone:** M3 · **Est:** 3d · **Depends:** SV-1, AU-1 · **Status:** in-review

## Story
The full server playback loop: pick a track on Jellyfin, stream it with header auth through our DSP, report position so the server dashboard and scrobble plugins see reality, and accept remote-control commands from other Jellyfin clients (play/pause/next/seek) as if we were an official app.

## Tasks
- [x] Direct-play stream: `GET /Audio/{id}/stream?static=true` via our libcurl layer with `Authorization: MediaBrowser Token=...` (no token in URL), Range-capable, fed to libvlc via `libvlc_media_new_callbacks` (no temp files). — `JellyfinStream` (`src/servers/jellyfin/JellyfinStream.{hpp,cpp}`) is a `std::streambuf` over the static endpoint: a seek inside the buffered response moves the get pointer, a seek outside re-requests with `Range: bytes=N-`, and `Content-Range`/`Content-Length` are parsed for size and the real start. `openJellyfinStream` wraps it as the `std::istream` that `ITrackSource::openStream` wants; fixtures replay the 200 and the 206, and the test pins the URL, the missing query auth and the Range header. The libvlc side: `VlcPcmTap::setMediaStream` calls `libvlc_media_new_callbacks` with open/read/seek/close statics and `JellyfinMediaSource` implements the `IMediaStreamSource` seam; `MediaRef::Kind::Stream` carries it through `PlaybackCore` (`engineStart`, `swapToNext`). ABI detail: libvlc hands the `datap` set by the *open* callback to read/seek/close, so open publishes the state pointer (a null there fails the first read with only "read error" in the log). The end-to-end test decodes an in-memory WAV served by a fake transport: libvlc read all 96044 bytes through the adapter. Open (not a checkbox): a streaming `IHttpTransport` — the current seam returns a whole body per request, so a far seek costs a round-trip.
- [x] Transcode fallback when the codec decision demands it; decision logic: direct unless unsupported-or-bandwidth-limited. — `JellyfinPlayback` plans `?static=true` or the AudioController's progressive form (`?static=false&audioCodec=aac&audioBitRate=192000&maxAudioChannels=2`), and `media.server.playMethod` carries `DirectPlay`/`Transcode` into the reports. **Deliberate deviation from the spec's HLS wording:** libvlc's HTTP access can attach only referrer/user-agent, not our Authorization header, so `master.m3u8` and its child requests would force the token into URLs — the header-auth rule wins. Both forms therefore travel the callback path. Revisiting HLS needs a spec PR (loopback auth proxy, or accept tokened URLs). Fixture `13-stream-transcode.json`; tests pin the URL, the codec policy, the bitrate cap and the absence of query credentials.
- [x] Wire RG: read `NormalizationGain` fields via the SV-1 gateway into the AU-1 ReplayGain stage. — `JellyfinClient::search` maps `NormalizationGain` into `Track::rg` (fixture asserts −6.2 dB) and `Container`/`Bitrate` into `Track::codec`/`bitrate`; `JellyfinPlayback::plan` copies the gain onto `MediaRef::rg`; `main.cpp` installs a `setTrackPrepareHook` that feeds it to `DspPipeline::setReplayGain` before the first block (and reads `RgTagSource` tags for local paths). Album mode still falls back to the track value.
- [x] Progress reporting: `POST /Sessions/Playing` (start), `/Sessions/Playing/Progress` (every 10s + on pause/unpause/seek/volume/track-change events, `EventName` set), `/Sessions/Playing/Stopped` (end) — `PlayMethod` correct per mode, `PlaySessionId` per queue session. — Gateway: `JellyfinClient::reportPlayback(baseUrl, token, deviceId, PlaybackEvent{Start,Progress,Stop}, PlaybackReport)` posts the koalapaw payload shape (`ItemId`, `MediaSourceId`, `PlaySessionId`, `PlayMethod`, `PositionTicks`, `IsPaused`, `IsMuted`, `VolumeLevel`, `CanSeek`, `EventName`), token in the header only, fixture-replayed on all three endpoints. Player wiring: `JellyfinPlaybackReporter` — observer callbacks only queue state; `tick(nowMs)` sends Start/Progress/Stop, the 10 s `TimeUpdate` heartbeat and immediate `Pause`/`Unpause`/`Seek`/`VolumeChange` events (a seek is a >2 s position jump). One `PlaySessionId` per queue session, reused across a gapless track change (Stop old + Start new), cleared on Stop. Tests drive a recording transport and pin cadence, payloads and session lifecycle. Attach point: add it as a `PlaybackCore` observer and call `tick` from the GUI timer once server playback can start in-app.
- [x] WS client for `/socket` (auth via header/first-frame handshake per koalapaw's AuthInterceptor pattern — **no query-string credential**): handle `Play` (PlayNow/PlayNext/PlayLast), `Playstate` (Stop/Pause/Unpause/NextTrack/PreviousTrack/Seek), `GeneralCommand` (SetVolume, Seek, PlayPause), `KeepAlive` reply loop on `ForceKeepAlive`. — `CurlWebSocketTransport` performs the HTTP upgrade over a libcurl `CONNECT_ONLY` handle (TLS and proxies included), sends masked frames, validates `Sec-WebSocket-Accept`, answers pings, consumes close/pong. `JellyfinRemoteClient` parses the catalog, replies `{"MessageType":"KeepAlive"}` on `ForceKeepAlive`, and returns `ServerRestarting` so the caller reconnects with `backoffFor` (1→2→4… capped at 30 s). Tests assert the upgrade carries the MediaBrowser header and that the request line carries no token.
- [x] Remote control maps onto the queue (server says "play next" → enqueue, not hijack). — `PlaybackRemoteAdapter`: `PlayNow` clears the queue and starts the first item (rest queued), `PlayNext` uses the new `PlaybackCore::enqueueNext` (front of the queue), `PlayLast` appends; cast items resolve through a callback and unresolvable ids are dropped rather than queued. Test with a real Null-output core: PlayNext lands at the queue front and playback stays stopped.
- [x] E2E/fixture tests for the WS message catalog. — Scripted frames cover Play/Playstate/GeneralCommand, keepalive, ServerRestarting, the upgade request and the queue mapping. The *live* container E2E (dashboard position within ±5 s, 30-min soak) still needs the server-browser UI to start a play; it stays as the acceptance follow-up rather than a fixture claim.

## Acceptance
- E2E: play/pause/seek a track; a second client's session dashboard shows our position within ±5s. — **not yet run**: requires the server browser + live containers; the reporter and transport are in place and fixture-tested.
- A cast from another Jellyfin client (or fixture-replay of `Play`/`Playstate` frames) controls us: play/pause/next/seek all work. — **fixture-replay proven** (parser + router + adapter against a real core); live cast pending the same UI hookup.
- Transcode fallback triggers when a deliberately-unsupported codec is forced (fixture), and `PlayMethod` reflects it. — **proven** (`dsf` → `Transcode`, FLAC → `DirectPlay`).
- WS auth carries the token in headers, never the URL (grep assertion over recorded handshakes). — **proven** (`handshakeRequest()` test + the static no-token grep).
- 30-min stream session: no buffer stalls on LAN, no socket leaks. — **not yet run** (needs a live server and the playback UI).

## Notes / risks
- `PlayMethod` correctness matters: it feeds server-side scrobble plugins; reporting DirectStream when we direct-play breaks their accounting. This implementation reports `DirectPlay` or `Transcode`, never `DirectStream`.
- WS reconnect: server restarts push `ServerRestarting` — reconnect with backoff and re-report the current session.
- Transcode is progressive, not HLS (see the Transcode task): keeps the header-auth guarantee, but the server's HLS-only edge cases (segment expiry, live playlists) do not apply to us. A spec PR is needed if HLS becomes a requirement.
- The reporter performs its HTTP only in `tick()`; observer callbacks never block the playback dispatch thread. The app timer is its only scheduler.
